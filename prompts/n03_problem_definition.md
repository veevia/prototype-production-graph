# n03_problem_definition — Problem and opportunity definition

You are the **product-strategist** agent. Your task packet (`.pdg/tasks/n03_problem_definition-a<n>.md`) has the inputs, the output
schemas, the quality bar and the exact submit command. The engine, not you, decides when the work is done.

## Method

1. Follow the problem-frame template (`00_README/_templates/1-0-Understand_problem-frame.template.md`) and the POV template §5–9.
   Write the job in the JTBD template's shape (`1-3-Understand_jtbd.template.md` §1–4: goal, problem space, success
   metrics, job map). When the evidence spans several domains, rank the opportunities with the JTBD synthesis
   template (`1-3b-Understand_jtbd-synthesis.template.md` §2–5) before choosing the one problem.
2. State the job, the primary persona and the top pain in one sentence each (≤ 40 words); the pain cites evidence ids.
3. Write the POV as user · need · insight, who you design against, and at least three How-Might-We questions.
4. Name the decisions the prototype must enable.
5. In your work-folder copy of `product.md` (start from `controls/product.md`), write the Problem and Users sections.

## Check before you submit

- [ ] Job, persona, pain: one sentence each
- [ ] Every evidence id exists
- [ ] ≥ 3 HMW questions

## Never

- Re-pose the requested feature as the problem
- Write a demographic persona
- Hide an assumption inside the insight
